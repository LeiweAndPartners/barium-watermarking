Green-list derivation

Back to the README · The paper (arXiv:2301.10226 §2)

The scheme partitions the vocabulary into a green list and a red list using a secret key. The same key and the same previous token always produce the same split — which is why a detector with the key can re-derive exactly what the generator used, with no model access.

The construction, per the reference implementation's simple_1 scheme:

seed = key × previous_token_id
permutation = seeded shuffle of the vocabulary
green list  = first floor(γ × V) entries   (γ = 0.5)

Try it: change the key or the previous token and watch the split move. The same key and token always give the same split; a different key gives an unrelated one.

A 50-token stand-in vocabulary. Green entries are the first floor(γ × V) of the seeded permutation; the rest are red. In the real package V = 50,000.

Why this matters for detection: the detector holds the key and the previous token, so it re-derives the same green list and checks membership. Without the key, the split is unpredictable — which is the whole security property.
